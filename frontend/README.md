# CobWeb Frontend

기존 Spring Boot 백엔드에 연결된 React 18 / Vite 화면입니다. 화면·공통 스타일의 출처는 저장소 루트의 `cobweb2026-oh-main.zip`입니다. 원본 ZIP은 비교·복원용으로 동결 보존하며 수정하지 않습니다. 실제 개발 대상은 ZIP에서 이식한 `frontend/src/`입니다. ZIP 내부의 당시 README나 mock 설명은 현재 서비스 동작 명세가 아닙니다.

## 실행과 빌드

전체 로컬 실행에는 Java JDK 21, Node.js 20 이상/npm, 실행 중인 Docker Desktop/Engine이 필요합니다. 저장소 루트에서 실행합니다.

```sh
./run.sh
```

웹·별도 채점 워커·전용 MySQL을 실행합니다. `Ctrl+C`로 이 실행의 프로세스와 DB를 중지하며 DB 데이터는 보존합니다. HTTP는 `http://localhost:8080`, 개발 HTTPS는 `https://localhost:8443`입니다. 자체서명 개발 인증서는 자동으로 신뢰되지 않으며 브라우저 보안 설정이나 시스템 CA 신뢰를 자동 변경하지 않습니다. HTTPS 설정·실행 옵션은 [루트 README](../README.md)를 참고하세요.

프론트엔드만 개발할 때에는 먼저 동일한 백엔드를 8080 포트에 실행한 뒤 사용합니다.

```sh
npm --prefix frontend ci --ignore-scripts --no-audit --no-fund
npm --prefix frontend run dev
```

Vite 개발 주소는 `http://127.0.0.1:5173/`입니다. 개발 시 화면 base는 `/`, 배포 빌드의 자산 base만 `/ui/`를 사용합니다. `/api`와 Markdown·코드 편집기 공유 스크립트는 `http://127.0.0.1:8080`으로 프록시되므로 프론트만 켜서는 로그인·조회·채점이 작동하지 않습니다. 5173 개발 서버에서 실제 OAuth 콜백·Secure 쿠키 연동을 검증한 것으로 간주하지 마세요. 제공자 인증은 등록된 동일 출처의 HTTPS 주소와 백엔드 콜백 설정이 필요합니다.

```sh
npm --prefix frontend run build
```

빌드 결과는 `dist/`가 아니라 `build/generated-frontend/static/ui/`에 생성됩니다. Gradle `processResources`가 잠금 파일 기반 설치·프론트 빌드를 수행해 JAR의 `static/ui/`에 포함합니다. 서비스 화면 주소는 `/`, `/problems` 등이며 Spring의 알려진 화면 경로가 `/ui/index.html`로 내부 전달됩니다. `/ui/`는 배포 자산 위치이지 서비스의 화면 경로 접두사가 아닙니다. 이전 정적 화면은 `/legacy`에 보존합니다.

## 구현된 연동

- 인증: 아이디·비밀번호 로그인, JOIN 이메일 발송·8자리 코드 확인·가입, 비밀번호 재설정 3단계, Google/GitHub/Naver 인증 경로. 네이버 신규 가입은 보안 정책에 따라 중단하며 기존 연결 계정 로그인만 허용합니다.
- 세션: access token은 메모리에만 보관하고 refresh token은 서버의 HttpOnly 쿠키로 관리합니다. localStorage에는 화면 테마와 편집기 설정 boolean 네 개만 저장하며 소스 코드·토큰은 저장하지 않습니다. 쿠키 변경 요청 직렬화, 계정 세대별 응답 폐기, 재발급 subject 변경 시 원 요청 재전송 중단을 적용합니다. JWT의 서명·만료·권한 인증은 서버가 담당합니다.
- 문제: 공개 검색·난이도 표시, 17개 언어 카탈로그, 코드 제출·판정 조회, 문제 제작·예제/비공개 테스트/정답 코드 추가·파일 첨부, 초안·검수 요청·운영자 공개 관리.
- 그룹·코테: 가입·그룹 설정·역할별 권한·그룹 문제 검수, 시간제 시험·분리된 답안, 본인 기록·권한별 결과/감시 신호·다시 보기 설정. 웹의 복사·인쇄 억제나 창 전환 신호는 운영체제 캡처·다른 기기 사용을 완전히 차단하지 않습니다.
- 커뮤니티: 분류·공지·검색, 글·댓글·최대 대대댓글, 편집·삭제·복원 및 운영자 전용 변경 이력. 서버는 원문과 이력을 보존합니다.
- 프로필·랭킹·내 활동: 실제 공개/본인 프로필과 소개·GitHub 편집, 서버 순서의 랭킹, 일반 제출·해결 기록·가입 그룹. 공개 프로필은 `/users?username=...`와 `/api/profiles?username=...`를 사용해 기존 `..`·슬래시·유니코드 이름을 보존하며 이전 단일 경로 형식도 유지합니다. 일반 제출 최근 최대 50개와 공개 해결 최근 최대 100개 등 서버 반환 범위를 명시합니다.

`/steps`는 별도 교육 과정 API가 없으므로 현재 공개 문제 페이지를 서버 난이도로 묶어 보여 줍니다. 가상의 강의·진도·연속 학습·활동 통계나 mock 성공을 표시하지 않습니다. 없는 주소는 준비 중 기능으로 가장하지 않고 찾을 수 없는 페이지로 안내합니다. 모든 데이터 접근·작성·운영자 권한은 화면 표시와 별개로 서버에서 검사합니다.

## 보호된 프론트 회귀 검사

저장소 루트에서 실행합니다. 의존성 설치는 위의 `npm ci` 명령을 사용합니다.

```sh
npm --prefix frontend test
```

`scripts/run-tests.mjs`와 별도 `test-process.mjs`가 파일별로 순차 실행합니다. 부모 V8 힙 128MiB, 테스트 자식 힙 192MiB, 프로세스 그룹 RSS 512MiB, 파일별 외부 시간 20초, 출력 2MiB를 제한합니다. macOS/Linux의 `ps`로 감시하며 감시 실패나 한도 초과 시 해당 테스트 프로세스 그룹만 종료합니다. 테스트 이벤트 루프의 타이머만으로 제한하지 않습니다. 제한 없는 `node --test`나 여러 테스트 파일 동시 실행으로 우회하지 마세요.

이 회귀는 API 응답 fixture와 실제 React 컴포넌트의 계약·계정 전환·비공개 자료 처리 등을 확인합니다. 실제 DB·Docker 채점·브라우저·외부 서비스 통과를 뜻하지 않습니다. 소스 수정 후의 검증 결과와 중단 여부는 [PROGRESS.md](../PROGRESS.md)에 별도로 기록합니다.

## 검증 경계와 데이터 보호

사용자의 기존 DB나 실제 계정으로 파괴적인 테스트를 수행하지 않습니다. 서버 통합 검증은 별도 테스트 DB와 테스트용 설정으로 명시적으로 분리합니다. 프론트 테스트만 실행해서 운영 DB 연결·17언어 실제 채점·전체 서버 연동을 확인했다고 주장하지 않습니다.

OAuth·SMTP는 별도 스테이징 환경이 없어 실제 제공자/메일 연동을 검증하지 않았습니다. 키나 DB 비밀번호를 채팅·프론트 소스·번들·로그에 넣지 말고 백엔드 환경 설정으로 관리하세요. 외부 배포에서는 유효한 도메인·인증서·신뢰 프록시와 제공자 콜백/쿠키 설정을 별도로 확인해야 합니다.

API 요청·응답과 권한은 [백엔드 구현 명세](../docs/BACKEND_SPEC.md), 보안 검토는 [검토 기록](../docs/security/REVIEW.md)을 참고하세요.

## 2026-10-26 코드 편집기와 문제별 시작 코드

`src/components/CodeEditor.jsx`는 번들에 포함한 CodeMirror 6를 사용하며 일반 풀이, 그룹 시험 답안, 제작 화면의 시작 코드·정답 코드에 공통 적용합니다.
소스를 실행하거나 외부 언어 서버에 전송하지 않습니다. LLVM IR·엄랭은 전용 토큰 규칙을 사용하고 다른 언어의 문법으로 가장하지 않습니다.

- `편집기 설정`에서 문법 추천·괄호 자동 닫기·자동 들여쓰기·문법 강조를 각각 켜고 끌 수 있습니다.
- 추천은 17개 언어의 키워드, 주요 내장 이름, 문법 스니펫, 현재 문서에서 찾은 이름입니다. `Ctrl+Space`로 요청하고 Enter로 선택합니다.
  다른 문서나 서버의 단어는 섞지 않습니다. 외부 라이브러리의 전체 API·타입 분석·컴파일 진단을 제공하는 LSP 기능은 아닙니다.
- 괄호 닫기와 Enter 들여쓰기는 언어 구문에 따라 동작합니다. Tab은 공백 4개이며 Shift+Tab 내어쓰기와 Esc 다음 Tab 포커스 이동을 유지합니다.
  의미 없는 괄호 쌍을 엄랭에 삽입하지 않습니다. 설정 변경은 문서와 선택 영역을 초기화하지 않습니다.
- `cobweb.editor.preferences.v1`에는 `suggestions`, `brackets`, `indentation`, `highlight` boolean만 저장합니다.
  답안·정답·시작 코드의 편집 내용은 컴포넌트/화면 메모리에만 두며, 서버 저장 버튼·제출을 누른 경우에만 해당 API로 전송합니다.

언어를 처음 선택할 때 `problemModel.starterCode()`가 문제의 공개 `starterCodes`를 먼저 선택합니다. 언어별 초안이 이미 있으면 빈 문자열도
사용자가 작성한 상태로 보존하며 언어 변경으로 덮어쓰지 않습니다. 계정 전환·화면 이탈·다른 문제 이동은 답안을 초기화합니다.
제작 화면에서 언어별 공개 시작 코드를 추가·수정·삭제해 문제별 매개변수를 표시할 수 있으며, 비공개 `referenceSolutions`에서 자동 복사하지 않습니다.

기본 FUNCTION 틀은 서버가 `functionAbi: "CHAIN_LASER_V1"`을 반환한 문제에만 적용합니다. 레거시 함수 규격이 불명확하면 매개변수를 추정하지 않습니다.
시작 코드의 선언을 바꾸어도 채점 규격은 바뀌지 않습니다. 현재 FUNCTION은 `matrix`, `target`, 불리언 반환의 고정 ABI이며 범용 임의 함수형 채점은 아닙니다.
제작·공개·시험 API의 시작 코드 저장에는 백엔드 V15가 필요하고, 기존 데이터에서 정답을 가져오는 backfill은 하지 않습니다.
